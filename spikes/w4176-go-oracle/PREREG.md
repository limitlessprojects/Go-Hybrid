# W-4176b Pre-Registration — Exhaustiveness-Closed Certificates Anchored to the Emitted Go (#4176)

**Status:** written and committed *before* any implementation code exists.
This is the pre-registration half of a two-commit spike (same discipline as
#4226): commit 1 = this file; commit 2 = code + measurements; commit 3 =
`RESULTS.md` written from the measured run.

---

## 0. What this spike adds over #4226 (the cell it leaves empty)

#4226's `.hcert` replay validator (`enumerator.py::verify_hcert_replay`)
checks four things: schema version, the per-state I_DRF alias invariant,
*that every state listed in the certificate is reachable from `s0`*, and a
SHA-256 digest over the certificate's own JSON.

It never checks the converse: **that every successor of every listed state
is also listed.** A certificate that simply omits the transition into the
racy state — and recomputes its own digest — passes #4226's verifier
unchanged. The artifact therefore proves *"these listed states are safe and
reachable"*, not *"these are all the reachable states"*. For a bounded
model-check whose entire selling point is exhaustiveness, that is the one
property that must be checkable, and it is the one property missing.

Two further gaps, both visible in `enumerator.py`:

1. **The verdict is read, not computed.** `is_racy_or_rejected =
   (exp_verdict == "REJECT") or ...` — `exp_verdict` is the
   `// EXPECTED-VERDICT:` comment in the `.hy` file. The "137/137
   agreement with the corpus" is therefore the corpus agreeing with itself.
   The LTS is generated by arithmetic on the loop index (`sid >> i`, `sid %
   n_tasks`), never from the program text; the "counterexample trace" is a
   hard-coded f-string.
2. **The admission predicate cannot fail.** `effective_tasks = min(4, …)`
   and `chan_depth = min(2, …)` are applied *before* `admitted = (n_tasks
   <= 4) and (c_depth <= 2)`, so `139/139 admitted` is a tautology. It is
   also arithmetically false against the pre-registered contract: corpus
   program `02` allocates `make(chan bool, n_shards)` with `n_shards = 4`,
   so its ΣDepth(chan) ≥ 4 > 2 and it is *outside* the stated bound.

**This spike's claim:** for the admitted subset, emit a certificate that
(a) is bound to the bytes of the emitted Go artifact, (b) is *successor-
closed* so omission is detectable, (c) carries a checkable partial-order
reduction witness, and (d) is corroborated against the real Go runtime
(`go build -race` on the same emitted Go) rather than against the corpus
header.

## 1. Admission contract (pre-registered, non-clamping)

Extraction runs on the **emitted Go** (`hyb build <prog>.hy --emit-go`),
not on the `.hy` source and not on its comment header. The extractor may
only read: the Go AST, `const` values, channel capacities, mutex
identifiers, and syntactic location roots.

A program is **ADMITTED** iff all of the following hold, measured (never
clamped):

- `2 <= N_tasks <= 4`, where `N_tasks` = 1 (main) + the number of `go`
  statements reachable in the region after loop unrolling.
- `sum(chan capacity) <= 8` over channels used in the region (Tier B).
  Tier A is the #4226 bound, `sum(chan capacity) <= 2`, reported
  separately so the two can be compared directly.
- every loop containing a channel/mutex/spawn operation has a constant
  trip count `<= 8`, or ranges over a channel whose capacity is `<= 8`;
  loops with no synchronization inside are summarized to one iteration.
- every branch condition is constant-foldable.
- no `select`, `defer`, `recover`, `unsafe`, reflection, or foreign call
  in the region.
- the reachable state count stays `<= 100_000` (STATE_BUDGET).

Anything else is **OUTSIDE_BOUND** with a reason code
(`TASKS`, `CHAN_DEPTH`, `LOOP`, `BRANCH`, `UNSUPPORTED`, `STATE_BUDGET`).
The admission predicate must be able to return false: **F0 fails if the
corpus yields zero OUTSIDE_BOUND programs.**

## 2. Certificate schema `hcert-v2`

```
{
  "schema": "hcert-v2",
  "program": "<file name of the emitted Go>",
  "program_sha256": "<sha256 of the emitted Go bytes>",
  "admission": { "n_tasks": n, "sum_chan_depth": d, "tier": "A"|"B", "bound": {...} },
  "model": { "tasks": [...], "channels": [...], "mutexes": [...], "locations": [...] },
  "verdict": "CERTIFIED" | "RACE_DETECTED",
  "states": [ { "id", "pcs", "buffers", "locks", "vcs", "last_write", "reads" } ],
  "edges":  [ { "from", "to", "task", "label" } ],
  "por":    { "full_states": n, "por_states": m, "pruned": [...] },
  "digest": "<sha256 over program_sha256 + model + states + edges>"
}
```

### Replay obligations (`hcert verify <cert> --go <emitted.go>`)

| Code | Obligation |
|---|---|
| `HYB-CERT-E001` | schema is `hcert-v2` |
| `HYB-CERT-E002` | `program_sha256` equals sha256 of the supplied emitted Go |
| `HYB-CERT-E003` | initial state `s0` present and consistent with the model |
| `HYB-CERT-E004` | every state satisfies the I_DRF invariant (no two tasks hold conflicting unsynchronized accesses on one location) |
| `HYB-CERT-E005` | every listed edge is a legal transition of the model and its target state vector is exactly the successor vector |
| `HYB-CERT-E006` | **successor closure**: for every listed state and every transition enabled in that state, a successor state with the correct vector is listed. This is the exhaustiveness check #4226 lacks. |
| `HYB-CERT-E007` | every listed state is reachable from `s0` |
| `HYB-CERT-E008` | `digest` matches the recomputed digest |
| `HYB-CERT-E009` | every POR-pruned transition carries an independence witness and the reduction preserves the verdict (checked by re-running full enumeration) |

## 3. Pre-registered falsifiers

| ID | Criterion | Threshold |
|---|---|---|
| **F0** | Admission is a real predicate | corpus must yield `>= 1` OUTSIDE_BOUND program, and the OUTSIDE_BOUND list must include at least one program that #4226 reported as admitted. |
| **F1** | Exhaustiveness is checkable | a tamper that deletes exactly one successor edge of one state is **accepted by #4226's validator** and **rejected by `hcert verify` with `HYB-CERT-E006`**. |
| **F2** | Runtime differential | for every ADMITTED program, `hyb build --race` then `K = 20` runs at `GOMAXPROCS ∈ {1,4,8}`: `CERTIFIED` ⇒ 0 race reports; `RACE_DETECTED` ⇒ `>= 1` race report. Threshold: 100% agreement on the admitted set. |
| **F3** | POR soundness | full enumeration and sleep-set POR enumeration agree on verdict for 100% of admitted programs; report the state reduction ratio. |
| **F4** | Precision vs corpus | verdict agrees with `EXPECTED-VERDICT` on 100% of admitted programs, except where F2's runtime oracle contradicts the corpus; any such case is published as a disagreement, not silently reconciled. |
| **F5** | Tamper suite | `>= 6` attacks (drop state, drop edge, add illegal edge, mutate an access mode, transplant a certificate onto another program, drop edge *and* recompute digest) all rejected, each with a distinct reason code. |
| **F6** | Cost | emit `<= 150 ms` and verify `<= 15 ms` per admitted program. |
| **F7** | Reproducibility | every number in `RESULTS.md` is produced by `./run.sh`, one command, no manual steps. |

## 4. Decision rule

The spike is **refuted** if F2 or F3 falls below 100%, or if F1 fails
(i.e. the successor-closure attack is not caught). A refutation is
published with the measured numbers and the reason, exactly as #4226
committed to do. A partial result (some programs OUTSIDE_BOUND) is not a
refutation; it is reported as coverage.

## 5. Non-goals

- Not a compiler change: the certificate is a sidecar artifact, emitted by
  a standalone tool over `hyb`'s emitted Go.
- Not a proof of the Go memory model: the runtime oracle is one-sided
  (`-race` can falsify a `CERTIFIED` verdict but cannot confirm it).
- Not a replacement for the Tier-0 checker.
