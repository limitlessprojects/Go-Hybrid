## 1. Executive Summary & Core Breakthrough

Proposal #4729 poses a fundamental question in library evolution:
> *"Give a package maintainer a concrete answer to 'which client stops compiling if I ship this ownership change?' Compare two revisions of a small checked API and produce a downstream `.hy` program that passes with the old release and fails with the candidate."*

Conventional API diff tools (such as `gorelease` or `apidiff`) inspect only surface syntax: parameter types, return types, and identifiers. When an API changes from **borrowing** an argument (`Preserves`) to **consuming** it (`Consumes`), the surface Go signature `func Submit(x *Resource)` remains completely identical, yet any downstream client reusing `x` after `Submit(x)` immediately breaks at compile-time with `HYB-E3003` (use-after-move).

### Breakthrough Highlights:
1. **Directional Ownership Lattice ($\sqsubseteq$)**:
   - Proves that ownership contracts form a partial order: $\text{Consumes} \sqsubset \text{Preserves}$.
   - Weakening rights ($\text{Preserves} \to \text{Consumes}$) is **directionally breaking**; strengthening rights ($\text{Consumes} \to \text{Preserves}$) is an **admissible relaxation** admitting strictly more clients ($\mathcal{W} = \emptyset$).
2. **Minimal Witness Synthesis**:
   - Implements a Breadth-First Search (BFS) synthesizer that finds the minimal-length sequence of API calls $w^* = [op_1, op_2, \dots, op_k]$ where $\text{Compile}(V_{\text{old}}, w^*) = \text{PASS}$ and $\text{Compile}(V_{\text{new}}, w^*) = \text{FAIL}$.
   - Automatically generates a standalone, compilable `.hy` fixture witnessing the breaking change.
3. **Exhaustive State-Space Proof (The 127-Sequence Census)**:
   - Evaluated all 127 call sequences of length $0 \dots 6$ across `{Submit, Inspect}`.
   - Proves that Borrow $\to$ Consume produces exactly **114 breaking witnesses**, with the minimal witness being `Submit; Inspect` (length 2).
   - Proves that Consume $\to$ Borrow (relaxation) produces **0 breaking witnesses**.
   - Proves that unchanged APIs produce **0 breaking witnesses**.
   - Raw pointer aliasing or unbounded callbacks safely return **`UNKNOWN`**.

## 2. Mathematical Formulation: Directional Contract Lattice

Let an API method $m$ define an ownership effect $E(m) \in \mathcal{E}$:
$$\mathcal{E} = \{\text{Consumes}, \text{Preserves}, \text{Produces}, \text{Unsupported}\}$$

The compatibility ordering $\sqsubseteq$ is defined as:
$$\text{Consumes} \sqsubset \text{Preserves}$$

For a client state $S \in \{\text{Live}, \text{Consumed}, \text{Poisoned}\}$:
$$\delta(\text{Preserves}, \text{Live}) = \text{Live}$$
$$\delta(\text{Consumes}, \text{Live}) = \text{Consumed}$$
$$\delta(\cdot, \text{Consumed}) = \text{Poisoned} \quad (\text{triggers } \text{HYB-E3003})$$

### Theorem (Directional Monotonicity):
For any sequence of operations $w = [op_1, \dots, op_k]$, if $\forall i, E_{\text{new}}(op_i) \sqsupseteq E_{\text{old}}(op_i)$, then:
$$\text{Valid}(w, V_{\text{old}}) \implies \text{Valid}(w, V_{\text{new}})$$
*Proof*: Since $E_{\text{new}}(op_i) \sqsupseteq E_{\text{old}}(op_i)$, each step preserves at least as many permissions as $E_{\text{old}}$. Hence, no state transition enters $\text{Consumed}$ or $\text{Poisoned}$ earlier under $V_{\text{new}}$ than under $V_{\text{old}}$. Consequently, no breaking witness can exist ($\mathcal{W} = \emptyset$). $\blacksquare$
