## 3. Three-state output

Every region terminates with exactly one verdict:

- **ADMIT**: attractor found, rank certificate valid, all falsifiers pass
- **REJECT**: at least one falsifier produces a counterexample
- **UNKNOWN**: budget exhausted or rank certificate absent; no claim

## 4. delshafy falsifiers (F1–F3)

All three falsifiers must be exercised per region. A region is ADMIT only if all three produce no counterexample within budget.

### F1 — `parallelism_ratio >= k_min > 1`

Computes the ratio of concurrent progress steps to serial steps. A counterexample exists if `parallelism_ratio < k_min` or `k_min <= 1`. F1 is P4-falsifiable: a single trace exhibiting serial-dominated progress refutes the claim.

### F2 — M1 Option 1 single-basic-block preemption-free step vs M2

Compares two progress-strategy machine variants:
- **M1 Option 1**: single-basic-block step, preemption-free within the block
- **M2**: multi-block step with preemption points

Counterexample: M1 exhibits a preemption point inside a nominally preemption-free block, or M2 achieves strictly better rank descent than M1 on the same region.

### F3 — Runtime domain witness with explicit losing sink

Constructs a runtime witness trace that drives the state machine into an explicitly designated losing sink. Counterexample: the witness trace reaches the losing sink despite all rank and channel-close invariants claiming safety.

## 5. GUARANTEES.md row 16 — checked-subset boundary

GUARANTEES.md row 16 (Send-on-closed-channel panics) states **No claim** — the checker proves value sendability, not send/close protocol ordering. This spike extends the checked-subset boundary as follows:

- **W-006 row-12 precedent**: checked-subset claims require every value crossing a `task` spawn or channel send to be verified sendable by Tier-0 rules.
- **Coordinator pre-terminal-attractor channel-close**: the coordinator must not close a channel before the attractor reaches its terminal state; send-after-close is prohibited within the checked subset.
- **Strictly decreasing rank**: every progress step must exhibit a strictly decreasing rank certificate; rank plateaus place the region outside the checked-subset guarantee.
- **Tier-0 no claim**: send/close protocol ordering (row 16) remains outside Tier-0 scope; this spike documents the boundary, it does not extend the checker.
